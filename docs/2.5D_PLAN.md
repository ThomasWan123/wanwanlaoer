# 2.5D 演进计划 — 斜投影立体战场（阶段 A）

> **状态**：执行中 · **目标**：在不引入 3D 引擎、不依赖 3D 模型的前提下，让战场从纯俯视升级为带纵深感的 3/4 视角
> **原则**：游戏逻辑层零改动；只改渲染层；AI 全自动可完成

## 为什么不能直接上真 3D

当前引擎是 **WebView + Canvas 2D**（`canvas.getContext("2d")`），所有渲染均为扁平的
`ctx.fill()` / `ctx.ellipse()` / `drawImage()` 指令。没有 WebGL、没有投影矩阵、没有深度
缓冲。26 个 JS 文件的坐标系全部是 `{x, y}`（无 Z 轴）。直接换引擎 = 全部重写。

## Unity 版失败教训（`D:\GT-123\game\UnityVer`）

已存在一次完整的 Unity 3D 重制尝试，**最终失败**。核心教训：

### 失败原因 1：3D 模型是无法逾越的瓶颈

Unity 版尝试了所有可能的 3D 角色方案，无一成功：
- **Unity 原生几何体堆叠**（`UnitVisuals.cs` 428 行）：球体头+胶囊身+立方体披风 → 效果如乐高积木
- **2D 立绘 → 3D 网格挤出**（`portrait_to_mesh.py`）：→ 纸片剪影，需 `fix_flat_meshes.py` 加厚度
- **AI 图生 3D**（Triposr / Trellis / Hunyuan3D，共 6 个 Python 脚本）：→ 网格薄、破面、风格不统一
- **广告牌**（2D 图贴 3D 平面）：→ 不是真 3D
- **浮雕**（`build-relief.log`）：→ 缺乏立体感

**结论：3D 角色模型无法靠 AI 或纯代码可靠生成，这是阶段 A 刻意回避 3D 模型的根本原因。**

### 失败原因 2：构建迭代速度灾难

- **80+ 个 Unity 构建日志**（`unity-build-*.log`）记录了反复挣扎
- 每次 Unity 构建 5–15 分钟，ADB 安装数分钟
- Canvas 2D 热重载 < 1 秒 → 迭代速度差 **100 倍以上**

### 失败原因 3：包体膨胀

- Unity APK：**824 MB**（`sanguo3d-debug.apk`）
- 本 2D 版 APK：~20 MB
- 899 个材质文件、2042 个 Resources 文件

### 失败原因 4：范围爆炸

- 重写了全部游戏逻辑：6,000 行 C#、37 个脚本
- 必须重新实现 30 关、38 将、27 种敌兵、9 种大招 → 引入大量新 bug

### 本方案如何规避以上全部问题

| Unity 失败点 | 本 2.5D 方案对策 |
|-------------|-----------------|
| 需要 3D 模型 | **完全不需要**——用 2D 立绘 + 投影 |
| 构建慢 | Canvas 2D 热重载 < 1 秒 |
| APK 824MB | 保持 ~20MB |
| 重写全部逻辑 | **游戏逻辑零改动**，只改渲染层 |

## 方案：斜投影（Oblique Projection）

采用 **倾斜俯视投影**（类似《Kingdom Rush》），而非完整等距旋转：

- X 轴不变（横向仍为横向，路径清晰可读）
- Y 轴压缩 0.72 倍（模拟相机前倾 ~40°）
- Z 轴（高度）沿屏幕 Y 轴向上偏移

### 投影参数

| 参数 | 值 | 含义 |
|------|----|------|
| `Y_SQUASH` | 0.72 | 地面 Y 压缩比（越小越倾斜） |
| `HEIGHT_SCALE` | 0.85 | 世界 Z 高度 → 屏幕像素转换比 |
| `SHADOW_ALPHA` | 0.35 | 地面投影阴影透明度 |

### 画布变换矩阵

```
ctx.setTransform(zoom, 0, 0, zoom * Y_SQUASH, -panX*zoom, -panY*zoom*Y_SQUASH)
```

### 高度提升

在 drawXxx() 中，实体先 `translate(x, y)` 到地面位置，再向上偏移：

```
ctx.translate(0, -height * HEIGHT_SCALE / Y_SQUASH)
```

- 全部数据文件（`paths.js`, `generals.js`, `levels.js`, `campaign.js` 等）
- 游戏逻辑（`tower.js`, `enemy.js`, `projectile.js` 的 update 逻辑）
- Java 原生壳
- UI HTML / CSS 结构

## 深度排序规则

```
所有可绘制实体（塔、敌人、障碍、投射物、特效）合并到一个数组，
按 depth = entity.y 升序排列（y 大的 = 靠近屏幕底部 = 后画）。
```

地图背景 → 视差层 → 排序后的实体 → 范围圈/预览 → 全屏覆盖。
